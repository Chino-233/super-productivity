## 这个分支中的个人日记扩展

此分支在原应用基础上增加了按日、周和月查看的日记。每日日历支持以 15 分钟为单位记录活动、拖动和调整时长、对比计划与实际，并可自定义常用活动。关联计划使用原有任务和日程；回顾页面也会显示原有任务用时，并共享每日反思内容。请参阅[日记与日历指南](docs/zh-CN/wiki/3.10-Journal-and-Calendar.md)。

## :heavy_check_mark: 功能

- **保持条理，专注当下！** 使用子任务、项目和标签规划任务并为其分类，还可以按需设置颜色。
- 使用**规划器**提前安排任务，在**日程**时间线上查看每日安排，并与日历事件并列显示。
- 在**看板**上直观整理任务，例如内置的 **Kanban** 和 **艾森豪威尔矩阵**，也可以创建自己的看板。
- 使用**时间盒**并**追踪用时**。轻松创建工时表和工作摘要，并导出到公司的时间追踪系统。
- 帮助你养成**健康高效的习惯**：
  - **休息提醒**会在该离开屏幕休息时提醒你。
  - **防拖延功能**会在你需要时帮助你理清思路。
  - 需要更专注？**专注模式**提供 **Pomodoro**、**Flowtime** 和**倒计时**时段。
  - **收集个人指标**，了解哪些工作习惯需要调整。
- 集成 **Jira**、**Trello**、**GitHub**、**GitLab**、**Gitea**、**OpenProject**、**Linear**、**ClickUp**、**Redmine**、**Nextcloud Deck** 和 **Azure DevOps**。自动导入分配给你的任务，在本地规划细节，自动创建工作日志，并在内容变化时立即收到通知。
- 基础 **CalDAV** 集成。
- 使用 **SuperSync**、**Dropbox** 和 **WebDAV** 支持，在多台设备间备份和同步数据。SuperSync 是我们自有的端到端加密同步服务，也可以[自行托管](https://github.com/super-productivity/super-productivity/tree/master/packages/super-sync-server)。
- 为任务和项目附加上下文信息。创建**笔记**、附加**文件**，或为链接、文件乃至命令添加**项目级书签**。
- Super Productivity **尊重你的隐私**，**不会收集任何数据**。无需账号或注册。**数据存在哪里由你决定！**
- 使用[**插件**](https://github.com/super-productivity/super-productivity/wiki/2.15-Develop-a-Plugin)和[**自定义主题**](https://github.com/super-productivity/super-productivity/wiki/3.09-Theming)扩展应用并更改样式。
- 支持 **Linux**、**macOS**、**Windows**、**Android**、**iOS** 和**浏览器**。
- **永久免费开源**。

还有更多功能！

## 文档：手动维护与自动生成

有两个 Wiki：由 GitHub 托管的官方 Wiki，以及使用 [DeepWiki.com](https://deepwiki.com/super-productivity/super-productivity) 自动生成的版本。手动维护的版本更稳定、易于阅读，旨在从更贴近用户的角度帮助你理解应用；DeepWiki 则侧重解释代码本身，对上下文关注较少。

<!-- Official Wiki -->
<h3>官方 Wiki</h3>
<p>
  最好维护本地文档，而不是依赖外部服务。
  也最好让文档随代码变更一同更新，<a href="https://github.com/super-productivity/super-productivity/commit/7a51d4b06e414fdcc48e4999197a93eee9cd09da">这个提交</a>就是一个例子。
</p>
<p>
  <code>./docs/wiki</code> 中的文件会在 CI 中进行检查，然后自动同步到 GitHub 托管的官方 Wiki。
</p>
<p>
  长期目标是在 Wiki 内容和结构成熟、剩余“旧文档”完成重写或删除后迁移到 Docusaurus。目前正在开发一些自动化工具，以缩小已发布文档与代码状态之间的差异，同时保留人工参与审核。
</p>

<!-- DeepWiki -->
<h3>DeepWiki.com</h3>
<p>
  如果你对代码的工作方式或某个错误为何产生特定消息有非常具体的问题，可以试试
  <a href="https://deepwiki.com/super-productivity/super-productivity">
    <img src="https://deepwiki.com/badge.svg" alt="向 DeepWiki 提问">
  </a>。在功能请求或错误报告中讨论自己尚未完全理解的功能和代码时，它可以帮助你“引用来源”。
</p>
<p>这类自动生成的<a href="https://diataxis.fr/reference/#reference">参考文档</a>也有一些明显缺点：</p>
<ol>
  <li><strong>意图：</strong>描述代码做什么，而不解释决策或权衡背后的原因。</li>
  <li><strong>过时：</strong>内容总会落后于代码。</li>
  <li><strong>侧重代码：</strong>不提供指南或概念说明。</li>
  <li><strong>成本：</strong>未来可能产生费用，且资源用量高于静态文档。</li>
</ol>
