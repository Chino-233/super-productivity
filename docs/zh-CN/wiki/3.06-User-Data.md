# 用户数据

**用户数据**这一概念**仅适用于桌面版（Electron）应用**。Web 应用使用浏览器存储（IndexedDB 和 localStorage）保存数据。Web 版与桌面版的区别请参见 [3.05-Web-App-vs-Desktop](../../wiki/3.05-Web-App-vs-Desktop.md)。关于导入、导出、备份和同步如何工作（面向用户的概览），请参见 [4.23-Managing-Your-Data](../../wiki/4.23-Managing-Your-Data.md)。

## 包含哪些数据

完整备份或导出是应用模型的可恢复快照，包含任务（活动任务和已归档任务）、项目、标签、时间追踪状态、全局配置、笔记、提醒、指标、简单计数器、规划器和看板状态、任务重复配置、问题服务设置、插件用户数据，以及两个归档层级（近期和较早归档）。它不是对每个本地数据库逐字节的完整复制。

日记页面会将实际和计划的活动时间段保存在每日日历指标的可选字段中。每日日记文字使用现有指标备注；次日计划、每周反思（保存在星期一）和每月反思（保存在每月第一天）也会保存在指标字段中。类别名称和颜色属于全局杂项配置的一部分。这些记录会包含在应用现有的备份和同步数据中。现有安装无需进行 schema 迁移。对同一天活动列表的并发编辑遵循现有指标冲突策略，不会逐条合并时间段。

设备本地的支持数据特意排除在该快照之外。例如，设备本地的崩溃安全编辑器草稿（localStorage `SUP_LOCAL_DRAFT_*`）、操作日志传输元数据、内部导入恢复槽、本地 REST API 访问令牌（`local-rest-api-token`），以及保存在独立 `sup-sync` 凭据数据库中的同步服务私有配置（凭据和加密密钥材料）。相反，应用模型中的问题服务设置可能包含 API 凭据或令牌。

普通备份和导出文件是**明文 JSON**，即使启用了同步加密也是如此。请将其视为敏感文件，像保护工作数据和其中可能包含的凭据一样妥善保管。匿名化/隐私导出会屏蔽已知字段名，但这并不能保证凭据安全：分享前请检查文件，并移除残留的服务提供方或插件凭据、令牌和私密内容。

## 用户数据文件夹的用途

“用户数据文件夹”是桌面应用保存以下内容的数据目录：

- 所有用户数据、设置和配置
- 自动备份
- 自定义主题文件（`styles.css`）
- 本地 REST API 访问令牌（`local-rest-api-token`）
- IndexedDB 和 localStorage 数据（由 Electron 管理）

## 各平台的默认位置

| 平台 | 位置 |
| ----------- | ----------------------------------------------------------------------------------------------- |
| **macOS** | `~/Library/Application Support/superProductivity/` |
| **Windows** | `C:\Users\<YOUR_USER_NAME>\AppData\Roaming\superProductivity/` 或 `%APPDATA%\superProductivity` |
| **Linux** | `~/.config/superProductivity/` |

备份路径会显示在界面的“设置 → 自动备份”下方（包括 `backups/` 子文件夹），也会在从命令行启动应用时打印出来。

### 自定义文件夹位置

可以通过命令行参数 `--user-data-dir` 指定自定义用户数据目录：

```bash
superproductivity --user-data-dir=/path/to/my/data
```

末尾的斜杠会被移除。当前会话将使用此自定义路径，而不是默认路径。

### Snap 软件包（Linux）

Linux 上的 Snap 软件包使用 `SNAP_USER_COMMON` 目录，以避免 Snap 更新进程访问数据。实际路径为 `$SNAP_USER_COMMON/.config/superProductivity`（或对应应用名称的目录）。

### Flatpak 软件包（Linux）

Flatpak 会将数据保存在软件包沙盒中。应用不会在这里设置自定义路径；Flatpak 会将 `XDG_CONFIG_HOME` 重定向到沙盒，因此实际路径为 `~/.var/app/com.super_productivity.SuperProductivity/config/superProductivity/`。准确位置可在“设置 → 自动备份”中查看。

沙盒会带来两个影响：

- 第二个非 Flatpak 安装（AppImage、`.deb`、Snap）会读取不同目录，**无法**看到这些数据。切换软件包格式时请使用导出/导入，不要并行安装后直接切换。
- 沙盒**外部**的同步或备份目标需要明确授予文件系统权限，可以通过 [Flatseal](https://flathub.org/apps/com.github.tchx84.Flatseal) 或 `flatpak override` 授权。未授权时应用会报告权限错误；`~/.var/app/` 中的路径始终可用。

### Windows Store

Windows Store 版本可能使用包含 Windows Store 软件包标识符的不同路径（位于 `Local\Packages\...\LocalCache\Roaming`，而不是 `Roaming` 下）。具体取决于 Windows 是否虚拟化该软件包：虚拟化软件包的 `AppData` 写入会重定向到 `LocalCache`，完全信任的软件包则写入普通 `Roaming` 路径。设置页面会显示你电脑上实际存在的位置；请查看页面，不要仅凭经验推断路径。

## 目录结构

### backups/ 子目录

- 保存自动备份文件（JSON）。
- 位置：`{userData}/backups/`。
- 桌面端自动备份文件的文件名格式为 `YYYY-MM-DD_HHmmss.json`。

### styles.css（可选）

- 桌面版的自定义样式主题文件。
- 需要由用户手动创建，并直接放入用户数据文件夹中（不能放在子文件夹内）。
- 文件由主进程加载并注入渲染进程；无效 CSS 可能无法加载，并会写入日志。
- 应用运行时会监视该文件：创建、编辑或替换文件后，会立即将新样式应用到打开的窗口，无需重启。清空或删除文件后，窗口中的样式也会立即移除。

### local-rest-api-token（可选）

- 首次启用本地 REST API（参见 [3.01-API](../../wiki/3.01-API.md)）时创建，直接位于用户数据文件夹中。在 macOS 和 Linux 上以 `0600` 模式写入（仅所有者可读写）；在 Windows 上继承文件夹的 ACL。
- 以明文形式包含 API 访问令牌——它属于凭据，不是设置。令牌**按设备区分**：它不属于应用状态，因此永远不会同步；从备份或导入恢复的设备会保留或生成自己的令牌。
- **不会包含在**自动备份、手动备份、“导出数据”或导入中——这些操作只处理应用状态。导入其他设备数据的设备仍使用自己的令牌；已有脚本可以继续使用“设置 → 其他 → 访问令牌”中显示的令牌。
- **会包含在**整个用户数据文件夹的冷拷贝中（文件级个人资料备份、磁盘映像、文件夹同步）。因此，此类副本含有有效 API 凭据：请像保护个人资料本身一样保护它，或之后在“设置 → 其他”中重新生成令牌。
- 删除此文件是安全的：下次启用 API 或在设置中读取令牌时，系统会重新生成令牌。继续使用旧令牌的脚本会收到 `401`。

### IndexedDB 和 localStorage（由 Electron 管理）

- IndexedDB 数据库和 localStorage 条目位于用户数据路径下因平台而异的位置。
- 由 Electron 管理；请勿手动移动或编辑这些文件。

## 文件类型与格式

### JSON 备份文件

- **格式：** 桌面端自动备份的文件名格式为 `YYYY-MM-DD_HHmmss.json`。
- **内容：** 序列化为明文 JSON 的可恢复应用模型快照。
- **命名：** 使用本地日期和时间加时间戳（例如 `2025-01-15_143022.json`）。

### CSS 主题文件

- **文件：** `styles.css`（必须使用此确切名称）。
- **用途：** 自定义 CSS 主题；由用户创建，可选。

### IndexedDB 数据库

- **SUP_OPS：** 保存运行时快照、保留的操作、因果元数据、归档和内部恢复状态的操作日志持久化数据库。可执行 schema 和升级逻辑由 `src/app/op-log/persistence/op-log-db-schema.ts` 和 `src/app/op-log/persistence/db-upgrade.ts` 定义；访问逻辑归 `OperationLogStoreService` 及其持久化适配器所有。
- **pf：** 用于迁移和恢复的旧数据库。
- **sup-sync：** 设备本地的同步服务凭据、私有配置和加密密钥材料，由 `src/app/op-log/sync-providers/credential-store.service.ts` 管理。此数据库不属于应用模型备份或导出的一部分。
- **SUPPluginCache：** 插件缓存。

已停用的冲突日志数据库（`SUP_CONFLICT_JOURNAL`）及其本地清除标记会在启动时删除，不会导出。此操作只会移除旧的复核条目；任务、待处理操作和备份会保留。如果旧标签页仍在占用数据库，待该连接关闭后才会完成清理。

### localStorage 键

界面和应用状态会使用如下键名保存在本地：

- `SUP_UI_HELPER`、`SUP_ACTION_LOG`、`SUP_LAST_ERROR_ACTION_LOG`
- `SUP_IS_PROJECT_LIST_EXPANDED`、`SUP_IS_TAG_LIST_EXPANDED`
- `DARK_MODE`、`SUP_NAV_SIDEBAR_EXPANDED`、`SUP_NAV_SIDEBAR_WIDTH`、`SUP_RIGHT_PANEL_WIDTH`
- `SUP_IS_ADD_TO_BOTTOM` 等其他键（完整列表见 `storage-keys.const.ts`）。
- `SUP_LOCAL_DRAFT_*`：设备本地的**崩溃安全编辑器草稿**，每项未完成编辑各占一个条目，键名为 `SUP_LOCAL_DRAFT_${entityType}:${entityId}`。这些草稿用于全屏笔记编辑器，确保崩溃或强制关闭后未保存的编辑仍然存在；它们**永远不会同步或上传**，也**不会包含在备份或导出中**——草稿是临时设备状态，不属于应用数据。草稿一旦变为多余就会删除：编辑保存或丢弃时、此设备上删除笔记时，以及整个数据集被替换时（JSON 导入、SuperSync 恢复）。应用启动时会清理从未重新打开且已超过 14 天的崩溃遗留草稿。

## 备份行为

**自动备份：** 在设置中启用后，应用会按计划创建备份（默认每 5 分钟一次）。此间隔和备份子目录无法在界面中配置。保存位置因平台而异：

| 平台 | 自动备份保存位置 |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Electron（桌面端）** | `{userData}/backups/`，保存为带时间戳的 JSON 文件（`YYYY-MM-DD_HHmmss.json`） |
| **Android** | 原生的应用私有 SQLite 存储（`SupKeyValStore`，最新和上一份备份对应的键为 `backup` / `backup_prev`），与 WebView IndexedDB 分开，因此 IndexedDB 被系统清理后仍可保留 |
| **iOS** | Capacitor Filesystem API：在 `Directory.Data` 中保存最新和上一份 JSON 文件 |
| **Web** | 不创建自动文件备份；请使用“导出数据”手动下载文件 |

桌面端的**最多保留的备份文件数**设置会限制 `backups/` 文件夹中保留的带时间戳自动备份数量。超过上限后会删除较旧文件。使用默认上限时，清理会保留最近 30 个备份文件，以及当前日期和之前 20 天内（存在文件的日期）每天最新的一份备份。由于每日备份可能与最近 30 个文件重叠，因此最终文件数可能更少。

在移动设备（Android/iOS）上，如果应用启动时没有本地数据，但设备上存在可用备份（通常是系统清理了 WebView 存储后应用变成空白的情况），应用会在启动时**自动恢复最新可用备份**，无需询问，并通过 snackbar 报告恢复了多少任务和项目。只有当当前存储确实为空时才会执行此操作；在应用内有意“删除所有数据”会留下有效的空状态，不会触发自动恢复。“恢复最新的自动备份”也可以在“设置 -> 同步与备份 -> 自动备份”中手动使用；页面会显示**上次备份**时间，方便确认数据受保护。手动恢复前会询问确认，并替换当前本地数据。桌面端不会自动恢复：如果应用启动时完全没有数据但存在备份，会询问是否恢复最新备份，并列出文件夹、时间戳以及其中的任务和项目数量，供你决定是否接受。如果已配置同步，恢复的数据（自动或手动）会作为备份导入处理；下次同步时会传播到并覆盖其他已同步设备的数据。因此请将其作为恢复操作，而非日常操作。

**手动备份：** (1) 在“设置 → 同步与导出”中点击**创建手动备份**，会使用与自动备份相同的机制创建备份（保存位置取决于平台）。(2) 某些同步操作前会自动创建**安全备份**；应用只保留有限数量的槽位（例如最近两份、当天第一份和前一天第一份）。(3)**导出数据**会将完整的应用模型快照作为 JSON 下载到你选择的路径（Web 版会保存到浏览器下载文件夹）。

**包含哪些内容：** 备份和导出包含上述可恢复的应用模型；如果请求归档，也包括两个归档层级。它们不会复制保留的操作日志、因果/传输元数据、设备本地的崩溃安全编辑器草稿（localStorage `SUP_LOCAL_DRAFT_*`）、内部导入恢复槽、单独保存的同步服务凭据和加密密钥材料，或本地 REST API 访问令牌（`local-rest-api-token`）——详见上文。另有一个单槽位的**导入备份**保存在本地 IndexedDB（`import_backup`）。应用会在通过文件导入或同步冲突操作**使用服务器数据**替换本地状态之前捕获此备份。成功执行“使用服务器数据”替换后，会显示一个持续存在的**撤销**操作，用于恢复此备份；同步恢复时，如果替换操作中断，也会提供相同的恢复操作。只要同一个备份仍然存在，应用重载后仍可使用“撤销”。此槽位属于内部恢复状态，不包含在导出文件或用户可见的自动/手动备份列表中。

应用模型快照仍可能包含私密工作内容，以及问题服务 API 凭据或令牌。同步加密不会加密其 JSON 序列化文件；请妥善保护普通备份/导出文件。匿名化/隐私导出只能尽力屏蔽信息，因此分享用于诊断前，请检查文件并移除任何残留凭据、令牌或私密内容。

## 导入与导出

**导出：** 导出会生成导出时当前状态的**快照**。文件是明文 JSON，其中包含（或封装）可恢复的应用模型状态。关系通过 ID 引用保留（例如任务引用 `projectId` 和 `tagIds`；子任务引用 `parentId`）。可以在“设置 → 同步与导出 → 导入/导出”中导出（例如点击“导出数据”/下载备份）。

**导入：** 应用接受同一格式的**完整备份**（完整应用模型状态，可选地使用时间戳和版本号封装）。支持以下结构：(1) 原始完整状态对象；(2) 包含 `data`、`timestamp` 和 `crossModelVersion` 的封装对象，其中 `data` 是完整状态。旧版 V1 格式（例如 `config` + `tasks` 数组）可以被识别，但**已不再支持**；应用会提示不支持迁移。应用在应用导入前会**验证**数据（包括结构和跨实体关系）。如果验证失败，在可行时可能会执行**自动修复**（例如修复孤立任务、无效项目/标签引用或缺失的归档结构）。如果快照记录的同步加密状态与当前应用不同，应用可能会在导入前显示**确认对话框**。该警告指的是导入状态将如何配置后续同步，并不代表备份文件本身已加密。导入后，当前状态会被替换；归档数据会写入 IndexedDB。如何执行恢复，请参见 [2.02-Restore-Data-From-Backup](../../wiki/2.02-Restore-Data-From-Backup.md)。

### 停止旧版本地数据迁移

目前仍支持将 **Super Productivity v16 或更早版本**的本地数据（旧版 `pf` 数据库）自动原地迁移到操作日志存储。该功能将在**2027 年 1 月 23 日之后的第一个版本**中停止支持。

停止支持后，如果本地数据尚未迁移，请先运行最后一个支持此迁移的版本，等待迁移完成，然后再升级到最新版本。确定后会在此处补充该过渡版本的版本号和下载说明。已迁移到操作日志存储的数据不需要经过过渡版本。

此停止计划适用于设备上的本地数据，包括浏览器存储。**仍支持导入受支持的旧版 JSON 备份**，请使用“从文件导入”；上文提到的现有 V1 不支持格式例外仍然适用。远程同步格式与此无关，不会因为本通知而停止支持。JSON 恢复说明请参见 [2.02-Restore-Data-From-Backup](../../wiki/2.02-Restore-Data-From-Backup.md)。

## 同步

**策略：** 应用采用本地优先设计，将更改记录为操作，然后根据不同传输方式调整操作日志。**SuperSync** 通过有序的服务器 API 发送操作。文件服务提供方默认使用单体 **v2** 格式：每次包含操作的上传都会重建并上传当前快照、两个归档层级和保留的操作。选择启用 **v3** 拆分格式后，这些部分会分别存储，因此普通操作上传不会在压缩操作日志期间重写快照。参见维护者现场指南中的[传输方式对比](../../sync-and-op-log/sync-architecture.html#transport)。

**冲突解决：** 应用通过向量时钟检测冲突（同一实体在两个位置被并发修改）。解决冲突时，首先应用明确的归档/删除优先级，并安全合并互不重叠的字段。剩余的重叠更改采用**最后写入优先（LWW）**：较新的操作时间戳获胜；如果时间戳完全相同，则按照稳定的客户端 ID 排序。当本地结果或合并结果必须同时高于两边历史记录时，应用会生成适当的更新、归档获胜或删除获胜操作，留待下次上传。**完全相同的冲突**会自动解决，无需用户操作。以下两种情况下，应用可能会显示对话框，让你选择**保留本地**或**保留远程**：**首次同步**时本地和远程都已有数据；自动解决在遇到无法安全合并的更改时停止（`SYNC_MULTI_ENTITY_UNSUPPORTED`）——参见 [3.08-Sync-Integration-Comparison](../../wiki/3.08-Sync-Integration-Comparison.md)。任一选项都会替换整个失败方数据集，而不只是冲突实体。解决后会验证状态，并在需要时进行修复。

## 用户可编辑与系统管理的数据

**用户可编辑：**

- **styles.css** — 可创建和编辑自定义主题。
- **备份文件** — 可通过“设置 → 同步与导出 → 导入/导出 → 从文件导入”恢复（参见 [2.02-Restore-Data-From-Backup](../../wiki/2.02-Restore-Data-From-Backup.md)）。

**系统管理（请勿手动编辑）：**

- IndexedDB 数据库。
- localStorage 条目。
- 活动备份文件（可按 JSON 读取，但不建议手动编辑）。

## 大小限制和配额

### 客户端 IndexedDB

- 出现 `QuotaExceededError` 时，应用会触发紧急压缩（保留 24 小时而不是 7 天），并使用断路器避免无限重试。
- 浏览器/操作系统配额和可用磁盘空间均会产生影响。

### SuperSync 服务器（如果使用；测试版）

- 默认配额：每位用户 100 MB。
- 超出配额时会自动清理。

## 权限

- 应用需要对用户数据文件夹拥有正常的读写权限。默认位置位于用户主目录或应用数据目录，不需要管理员/root 权限。
- 需要访问原生文件系统或进程的插件，必须获得 `nodeExecution` 权限，并在 Electron 桌面应用中取得明确同意。内置插件以及上传/社区插件都可能请求此权限。上传的插件会在原生提示中标记为未经验证的第三方代码；授予权限后，该插件可以使用与你的用户账户相同的机器访问权限运行代码。参见 [2.21-Manage-Plugins](../../wiki/2.21-Manage-Plugins.md)。

## 恢复与修复

### 自动数据修复

- 在操作生命周期的多个阶段执行验证。
- 修复孤立任务、无效引用和关系不一致等问题，并为操作日志创建 `REPAIR` 操作。

### 灾难恢复

- 如果主数据库（`SUP_OPS`）缺失或损坏，应用会尝试从旧版 `pf` 数据库加载数据并执行初始迁移。
- 如果恢复失败，则需要完整重新同步（或从备份恢复）。
- 如果旧版 `pf` 数据库迁移失败，迁移对话框会报告错误并等待。对话框还提供**在没有旧数据的情况下继续**，让应用使用空存储启动，而不是每次重启都卡在错误提示上。不会删除任何内容：`pf` 数据库仍留在磁盘上，只会添加 `_migration_skipped` 标记，因此后续迁移和恢复不再选取该数据库。之后可以正常导入迁移前自动创建的备份；未修改的 `pf` 数据库仍可作为第二份副本用于手动恢复。

### 从备份恢复

- 在“设置 → 同步与导出 → 导入/导出 → 从文件导入”中选择 `backups/` 目录里的备份文件。参见 [2.02-Restore-Data-From-Backup](../../wiki/2.02-Restore-Data-From-Backup.md)。

### 同步状态损坏

- 如果同步操作无法干净地应用，应用会标记同步状态并重新验证；完整重新同步可以恢复一致状态。

## 配置和版本管理

- 公共应用配置属于 `SUP_OPS` 中的模型快照；本地界面设置也会使用 localStorage（`SUP_*` 等相关键）。同步服务私有配置和密钥材料单独保存在 `sup-sync` 凭据数据库中。
- **数据库 schema：** 请将 `src/app/op-log/persistence/op-log-db-schema.ts` 和 `src/app/op-log/persistence/db-upgrade.ts` 视为可执行的事实来源；不要依赖文档中抄录的版本号或存储清单。
- **应用版本：** 由构建过程定义（例如 `src/environments/versions.ts`），不会保存在用户数据文件夹中。
- **备份文件：** 每个 JSON 文件都包含可恢复的应用模型快照；桌面自动备份文件名中包含日期和时间。

## 应用访问方式（桌面版）

- **主进程：** 通过 Electron `app.getPath('userData')` 获取路径；使用 `--user-data-dir` 或 Snap 逻辑时，通过 `app.setPath('userData', path)` 设置自定义路径。
- **渲染进程：** 通过 IPC 暴露路径（例如 `getUserDataPath()`）。
- **备份和文件同步：** 使用 Node.js `fs` API（例如 `readFileSync`、`writeFileSync`、`readdirSync`、`statSync`、`unlinkSync`）执行备份和本地文件同步。

## 备注

- **Web 应用：** 数据只保存在浏览器存储中，没有用户数据文件夹。参见 [3.05-Web-App-vs-Desktop](../../wiki/3.05-Web-App-vs-Desktop.md)。
- **不要对该文件夹进行实时同步：** 通用 WebDAV 或云文件夹工具可能会在 Electron 的 IndexedDB/LevelDB 文件和锁文件正在变化时复制它们，导致个人资料损坏或无法使用，同时还会上传明文备份和设备本地凭据。多设备同步请使用 Super Productivity 内置同步功能。若要冷备份个人资料，请先彻底关闭应用，再将整个文件夹作为一份敏感备份进行复制；恢复时也必须先关闭应用。
- **主题：** 示例主题和创建主题的指南见 [super-productivity-themes](https://github.com/super-productivity/super-productivity-themes)。

## 任务优先级兼容性

任务备份中可能包含数字优先级（`1`、`2`、`3`），也可能使用等效的旧版字符串（`low`、`medium`、`high`）。导入、同步、复制或从归档恢复时，两种格式都会保留。显示、排序和筛选会按其含义处理；选择其他优先级时会写入数字。清除优先级时会写入 `null`。

同一设备上保存的优先级筛选器重载后会保留所选级别，包括由使用旧版字符串的构建版本保存的筛选器。

旧版支持优先级的构建版本只接受一种编码。每台参与同步的设备都需要进行兼容性修复；更新一台设备无法修复另一台设备上的旧读取器。所有受影响的 master 构建版本都报告为 `19.1.0`，因此仅凭版本号无法判断客户端是否兼容。常规发布流程必须使用单独的未来版本发布修复。目前 SuperSync 不会强制要求最低应用版本。
