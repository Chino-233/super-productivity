# Journal and Calendar

Open **Journal** in the sidebar and choose a date or a daily, weekly or monthly view.

## Plan from month to week to day

These views plan at different scales. **Monthly planning** assigns an activity to an inclusive date range, for example October 12–16 for a report. Drag across dates in the month grid or choose **Add date range** and enter the start/end dates. Ranges can cross month boundaries and appear in each affected month. Enter a name, category and optional linked task or note; no clock time is required.

**Weekly time budgets** assigns hours to a particular day, for example two hours on October 14 for that report. Use **Open week** on a monthly plan, then **Allocate hours** on the desired day. Select the monthly source to carry over its name, category, task and note, or create an independent weekly activity. Hours use quarter-hour steps (0.25–24); one day's total budgets cannot exceed 24 hours. A linked task can have one budget per day. Each weekly card displays budgeted, scheduled, remaining and actual hours.

**Choose calendar time** opens the budget's day in the plan calendar. Click a 15-minute slot to start with the remaining budget duration, or drag a range to choose its duration. Review the times before saving. Split one budget into several non-overlapping daily segments as needed. The activity editor's **Weekly time budget** field can also associate an existing manual segment with a budget. Creating month/week plans never invents a daily start time.

Daily segments supply the scheduled/actual totals shown on weekly cards, and monthly plans total their linked weekly budgets and daily placements. These are derived views of the saved records. Recording a plan as actual retains its weekly source but requires review and saving; completing a task does not create actual time. Scheduling more than the budget is allowed, with remaining time shown as zero. Reducing a budget or editing its source does not rewrite existing daily segments.

Monthly/weekly journal text remains available for notes and review. **Daily records and reviews** expands the older per-day overview; it is secondary to planning. Deleting a monthly plan preserves weekly budgets and daily records; deleting a weekly budget preserves its daily segments. Removed sources can be replaced through the editors. Markdown exports include date ranges and weekly allocations alongside daily records.

## Record activities

The daily calendar uses 15-minute slots. Click a slot to open the activity editor or drag across slots to select a longer range. Enter a name, category and optional note, then save. Start/end times can also be entered manually; new intervals use quarter-hours and the end can be `24:00`.

Click an activity to edit it. Drag its body to move it while preserving duration, or drag either edge to resize. Changes stay within the day. If a manual change overlaps another entry of the same type, it is rejected and the original record remains. Native task schedules that already overlap appear side by side. **Plan vs actual** displays separate lanes; planned time does not count as actual recorded time. **List** provides edit/delete controls.

On touch screens, tap to record and swipe empty slots to scroll. Keyboard users can activate a slot or activity with Enter and use Up/Down to move a focused activity or resize a focused edge. Escape cancels an empty calendar selection. In the activity editor, Escape saves your edits and closes all open journal editors, just like **Close**.

## Common activities

**Customize** lets you add, rename or delete common activity templates. Only the shortcut's template name is required; activity name, category, plan/actual type, start, end, duration, linked task and multiline note are optional. Blank fields keep the current activity values. A blank activity name uses the current name, or the template name if the activity has no name yet. **Keep current value** preserves an existing task link; **No linked task** explicitly clears it for a new/manual activity. Editing an existing linked native plan always keeps its original task. Deleting a shortcut keeps past records. An empty saved list stays empty.

Choose a shortcut in the activity editor to fill its details. Fixed template start/end times override the selected range, with an explicit end taking priority over duration. Without fixed times, a dragged range longer than one slot keeps its duration. A clicked slot or panel shortcut uses a provided duration, capped at midnight; omitting all time fields keeps the current range. Times and durations use 15-minute steps; an end can be `24:00`. Review the times before saving.

**Save as common template** copies every field of the current activity editor into a new reusable template. This saves the shortcut only; the activity is saved when you choose **Save**, **Close**, or leave its editor. Templates do not start timers or create/change tasks until you save an actual activity or linked plan. If a preset's linked task is unavailable, the editor asks you to choose another task instead of applying that template.

In month/week views, a panel shortcut fills the planning editor's activity name, category, task and note while retaining its date selection. Weekly budgets also use the template duration, or its start/end difference, as hours. Clock times and plan/actual type remain daily-calendar concerns.

## Tasks and reviews

Select a **Linked task** to reuse an existing task. Linked plans edit the original task's name, notes, estimate and scheduled time. Changes made through the original task interface appear on the calendar automatically. Tasks scheduled with a start time appear in the plan lane; date-only tasks appear in the task overview without an invented start time.

**Create task** converts a manual plan into an original timed task. **Cancel schedule** clears its calendar placement and keeps the task. **Record as actual** opens a separate manual record for review and saving. Completing a task does not automatically claim that its planned time interval occurred.

Daily segments sourced from weekly budgets reference the original task without replacing its single native schedule, title or estimate. This allows several work sessions for one task. A native scheduled interval on the budget's day also contributes to its scheduled total. **Create task** on a budget segment creates a date-only task and keeps that segment and its weekly source. Task completion and timers still operate on the original task.

The task overview shows scheduled tasks, tasks completed in the period and recorded task time, including loaded archived history. Its checkboxes and play/pause controls use the original task system. Accumulated timer duration is shown separately from manual activity duration to avoid double counting; it cannot reconstruct exact historical execution intervals.

The daily page embeds the original reflection editor, so it and the daily summary edit the same reflection. Longer journal text remains separate in daily notes. Weekly/monthly views and Markdown exports include daily notes, reflections, activities and task information. Automatic views never overwrite personal journal text.

## Save on closing

Choosing **Daily journal**, **Weekly journal**, or **Monthly journal** saves the current journal text and plan, activity edits, template configuration, categories and daily reflection, then closes every open journal editor. Clicking the current period button does the same. Date navigation, changing the calendar/list view or activity type, leaving Journal through the sidebar, and exporting also use this rule. The activity editor is non-modal so the period buttons remain available while editing.

The monthly range and weekly budget editors use the same closing rule. Invalid date ranges, hours or monthly-source dates keep the editor open and show an error; other valid sections are saved. Opening a different planning editor first saves and closes the current ones.

**Close** and Escape save instead of discarding edits. Clicking **Customize** or **Categories and colors** again closes and saves all editors. Collapsing a template's optional fields saves the template configuration and journal text while leaving the template list available. An untouched empty activity editor creates no record, and unchanged editors do not rewrite stored data.

If an activity overlaps another or a field is invalid, valid sections are saved, but the editors stay open and show the error. Fix the invalid field before closing or navigating away; a browser close/reload requests confirmation while invalid edits remain. Daily reflections are saved immediately at these boundaries rather than waiting for their normal typing delay. Original task and global-settings dialogs retain their existing Save/Cancel behavior.

## Data compatibility

Common activities use an optional miscellaneous configuration field. Native task schedules remain on the original task, with an optional journal category. No new plugin API, entity type, operation type or schema migration is introduced. Existing clients can ignore the optional fields. Backups include these fields through existing task, metric and configuration storage. Daily activity lists retain the original metric conflict policy; concurrent edits are not merged per activity.

Monthly ranges and weekly budgets are optional arrays on the existing metric records, anchored at the first day of their creation month or week. Daily segments carry an optional weekly source and task-reference mode. Planning saves patch one metric through the existing update action, and progress is calculated locally. They inherit the metric conflict policy; concurrent edits are not merged per planning item.
